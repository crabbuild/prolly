# Store protocol-v2 payload history under immutable derived keys

Protocol v1 binds every logical object version to a provider `VersionId` at the original user key, so a finite per-key provider limit eventually makes a hot key unwritable and cannot be repaired without rewriting immutable history. Protocol v2 instead makes an immutable content-addressed payload key the authoritative physical binding, keeps delete markers logical-only, and treats any original-key materialization as a non-authoritative projection. This adds a distinct v2 binding and may add a projection request, but it bounds every physical payload key to one version, permits safe deduplication, and allows providers with finite limits when their limit still exceeds the configured mutable-control bound plus safety headroom; unknown limits fail qualification.
